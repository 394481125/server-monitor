# 功能需求评估与实现结论

更新日期：2026-08-17
适用版本：`v1.3.6` / schema `6`

本文把需求分成“本版实现”“只读/脚本实现”“已有能力”“暂缓”四类。平台定位是可信内网的轻量监控和受控运维，不是通用远程执行器或容器编排系统。

| 需求 | 必要性 | 结论 |

## 已有能力，不重复建设

- GPU 功耗、风扇、ECC、XID、PCIe、节流、硬件资产和 SMART 已有采集与页面。
- 主机标签、备注、保存视图、PWA、告警确认/批量软处置、指标保留设置、底部平台状态条已存在。
- 目录容量/大文件扫描已经有进度、超时、深度、结果上限和设置项。
- 手动 SSH 连通性测试、失败原因细分、Docker 容器基础列表和进程页面已存在。

## 只读或脚本实现

| 需求 | 处理方式 | 原因 |
| --- | --- | --- |
| systemd 重启 | 输出 `sudo systemctl restart ...` 脚本 | 避免网页直接中断 SSH、Docker 或采集服务。 |
| GPU 功耗墙 | 暂不执行，后续仅输出 `nvidia-smi -pl` 脚本 | 运行时修改仍可能影响训练任务。 |
| 环境备份 | 输出远端 tar + SHA256 脚本 | 不把大文件通过 Web 下载到浏览器。 |
| Docker 镜像导入/导出 | 暂缓，仅允许服务器本地脚本 | 避免 GB 级 HTTP 上传下载。 |
| cron 管理 | 暂缓，仅查看/脚本输出 | 不直接改动用户定时任务。 |

## 暂缓及原因

### 1. 浏览器端口转发

需求高频，但 Web 页面不能安全监听用户本地端口。平台服务器代监听又会引入端口冲突、横向代理、目标白名单和会话回收风险。现阶段使用：

```bash
ssh -N -L 16006:127.0.0.1:6006 user@server
ssh -N -L 18888:127.0.0.1:8888 user@server
```

未来必须配套独立客户端或受限代理网关、目标白名单、空闲回收、审计和并发限制。

### 2. 任意命令模板和批量 Shell

便利性高，但本质是多机远程代码执行。需要命令版本、审批/再认证、逐机超时和停止、输出上限、失败恢复、范围授权和完整审计后再加入。当前不提供“批量更新驱动/批量清缓存”。

### 3. GPU 残留显存一键清理

显存残留可能由驱动、MIG、容器或尚存但不可见的进程造成，无法仅凭 nvidia-smi 安全确定可杀对象。页面只标记疑似异常并告警，管理员可通过现有受控终端人工确认。

### 4. Docker 写管理和交互终端

Docker socket 权限通常等价 root。启动/删除/exec/构建/拉取/Volume 修改和 daemon.json 都会扩大平台的破坏半径。本版只读查看，写操作由管理员在主机本地或受控 SSH/Tmux 完成。

### 5. SSH 连接池、SFTP 真断点续传、实时进程 IO

当前以连接并发、空闲关闭、超时和累计 IO 计数控制复杂度。长连接池需要失效回收和凭据变更淘汰；断点续传需要分片/校验/配额；实时进程 IO 需要更高采集频率和额外权限。达到实际规模后再按数据投入。

### 6. 低优先级工具化需求

标签级告警抑制、状态颜色模板、备注模板、cron 修改、Base64 工具、定时快照调度和完整 OOM/dmesg 历史，对核心监控收益较低，先保持当前稳定实现。

## 验收

本轮测试覆盖 113 个自动化案例；浏览器验收使用临时数据库，检查 GPU 点击详情、GPU 用户汇总默认收起、告警提醒关闭/开启、批量处置后红点同步，以及 390px 手机无横向溢出。完整命令：

```bash
.venv/bin/python -m pytest -q
node --check monitor/static/app.js
.venv/bin/python -m compileall -q monitor tests scripts gunicorn.conf.py
.venv/bin/python -m pip check
git diff --check
```
