# Server Monitor 需求规格（V3.5.0）

版本：V3.5.0（开发环境与 GPU 软件栈管理修订）  
更新日期：2026-08-15  
状态：与当前源码、测试和部署文档一致

## 1. 产品定位

本系统面向可信内网的少量 Linux 服务器，使用 SSH 完成指标采集和受控运维，不在被管主机部署常驻 Agent。系统强调三项边界：平台不能伪造远端身份、危险操作必须明确授权、采集数据不能无限增长。

当前部署形态为一个 Flask 应用、一个 Gunicorn 实例、一个 SQLite 数据库和独立数据目录。不依赖 Redis、消息队列或外部时序数据库。

## 2. 需求优先级与实现结论

| --- | --- | --- |

| 批量 SSH 重测 | 已实现 | 报告指纹、物理身份和连接异常，不提供批量盲目确认。 |
| iowait、inode、TCP、监听端口 | 已实现 | 采集、最新快照、历史点位和主机详情均可见。 |
| 挂载点独立容量/inode 阈值 | 已实现 | 主机规则覆盖全局阈值，接入连续样本告警。 |
| 告警历史筛选、导出、故障聚合 | 已实现 | 服务端过滤，避免分页只筛当前 DOM。 |
| SFTP 文件/文件夹上传下载 | 已有 | 文件管理已支持目录 ZIP 下载，无需再造终端传输通道。 |

| GPU 软件栈盘点与自检 | 已实现 | 读取驱动推荐项、CUDA/cuDNN、ECC、拓扑、NVLink；显存碎片明确标记为不可由 `nvidia-smi` 提供。 |

| APT、驱动、CUDA、cuDNN 方案 | 已实现（脚本模式） | 生成固定模板供人工审阅；不通过网页直接改变内核、软件源或全局包。 |
| 目录容量与大文件扫描 | 已实现 | 限定绝对路径、跨文件系统和返回数量，部分无权限时返回警告。 |

| 进程长期占用告警 | 暂缓 | 需要高频进程快照、PID 重用处理和独立保留策略。 |
| GPU 抢占、阶梯阈值、泄漏预测、幂等重试、命令回滚 | 暂缓 | 需要重新设计调度任务状态机和审计快照。 |
| 批量 Shell、密钥分发、一键升级 | 暂缓 | 远程代码执行和供应链风险高于当前版本目标。 |
| 拖拽自定义大盘、Excel 报表、预测 | 暂缓 | 非基础故障发现能力，排在安全纳管和可观测性之后。 |

## 3. 角色、页面和权限

系统有管理员和普通用户两种基础角色。管理员拥有代码目录中定义的全部权限；普通用户的页面权限、操作权限和页面显示偏好均存储在数据库中。

- 页面包括集群概览、主机管理、文件管理、开发环境、调度记录、告警事件、审计日志、系统设置和权限与界面；主机详情有同构的开发环境标签页。
- 操作权限按主机、终端、Tmux、进程、工具安装、压力测试、GPU 调度、文件操作、备份和导出拆分。
- 后端每个接口独立校验登录、页面/操作权限、CSRF 和必要的再认证；前端隐藏按钮只是可用性处理，不是安全边界。
- 开发环境方案拆分为盘点、生成和执行权限；`apt.plan` 单独控制 APT 方案。目标主机还必须启用 `allow_install`，网页执行前要求平台密码复核。
- 管理员修改用户权限后删除目标用户会话；普通用户只能在已经获授的页面中选择显示或隐藏。
- 本版本没有平台层业务分组 ACL；需要主机范围隔离时使用不同平台账号与远端 Unix 用户/组，或在后续版本增加显式组模型。

## 4. 主机管理

### 4.1 主机字段

主机记录包含显示名、地址、SSH 端口、用户、密码或私钥认证、标签、备注、采集超时、Docker/Tmux/终端/进程/安装/压力测试能力开关和 GPU 调度配置。SSH 密码、私钥、私钥口令和 sudo 密码通过平台主密钥加密保存，查询列表只返回是否已配置。

### 4.2 身份与状态

首次连接由服务端读取 SSH 主机密钥指纹和 `/etc/machine-id`，计算物理节点标识。客户端提交的 identity 永远不可信。地址、端口、用户或凭据发生变化时必须重新测试；指纹变化返回 expected/observed 并停止保存，machine-id 同时变化还需单独确认物理节点替换。

状态包括在线、降级、采集繁忙、等待采样、离线、SSH 指纹异常和已禁用。核心采集连续三个周期失败才进入离线；主机成功一次核心采集后恢复在线。离线、指纹异常、禁用或采集繁忙时关联 GPU 状态清零为空闲未知。

### 4.3 批量纳管与重测

CSV/JSON 模板字段覆盖连接信息、标签和能力开关。单次导入最多 100 条、文件最多 2 MiB；每条记录独立执行连接、指纹、machine-id 和物理节点重复检查，接口返回逐条结果，允许部分成功。

导出只输出非敏感配置，JSON 带 `credentials_included: false`；密码、私钥、口令和 sudo 密码不得出现在 JSON、CSV、审计摘要或页面。批量重测只报告结果，不提供批量确认新指纹的接口。

## 5. 指标采集规范

### 5.1 核心指标

| 类别 | 指标 |
| --- | --- |
| CPU | 利用率、逻辑核心数、各核心利用率、iowait。首个样本只建立计数器。 |
| 内存 | 总量、可用、已用、利用率、Swap。 |
| 文件系统 | 容量总量/已用/可用/利用率，inode 总量/已用/可用/利用率，挂载点。 |
| 磁盘 IO | 物理设备读写速率、读写 IOPS、忙碌率。 |
| 网络 | 网卡收发速率、错误和丢弃。 |
| TCP | TCP 套接字总数、ESTABLISHED、TIME_WAIT。 |
| 监听端口 | TCP/UDP 协议、端口和监听地址，最多保留 256 项。 |
| GPU | 型号、UUID、利用率、显存、温度、功耗、进程。 |
| 可选能力 | Docker、SMART、CPU 温度、sensors、Tmux 等。 |

远端命令使用 `/proc/stat`、`/proc/meminfo`、`df -P`、`df -Pi`、`/proc/net/dev`、`/proc/diskstats` 和可选 `ss`。`ss`、SMART、sensors 等工具缺失时仅标记可选错误，不能丢弃同次核心指标。TCP 不保存完整连接表，防止高连接主机扩大 SSH 输出和数据库。

### 5.2 历史与容量

最新完整样本每台主机仅保留一份；指标点按 raw/mid/long 三层保存，默认原始 15 分钟、中期 6 小时、长期 7 天。采集任务只保存状态、时间、失败周期和错误摘要，不重复写入完整 data。后台每 5 分钟执行幂等聚合和过期清理。

### 5.3 阈值告警

系统设置提供文件系统容量和 inode 全局阈值；`mount_alert_thresholds(host_id, mountpoint)` 提供主机挂载点覆盖。容量和 inode 各自使用连续有效样本，达到阈值产生 warning，低于阈值减恢复回差后产生恢复 info。温度、主机离线、指纹和 GPU 调度沿用现有告警状态机。

## 6. 告警中心与通知

告警表记录事件键、主机、对象、类型、状态、严重级别、摘要、创建/发送/恢复时间。严重级别固定为 critical、warning、info；页面使用对应颜色和 Toast。告警中心可按主机、类型、活动/恢复状态、级别、时间范围和文本搜索，筛选结果可导出最多 10000 条 CSV。

故障聚合接口将离线、指纹异常、降级、繁忙主机和活动资源告警合并为主机列表，提供跳转主机详情入口。Server 酱是可选外部渠道，事件类型由管理员选择；本地 Web 页面和数据库历史是内网基础能力。dmesg/journal 只可通过受控终端按需查看，本版本不周期落库。

## 7. 远程运维和文件

- Web 终端通过 SSH PTY 或 Tmux，xterm.js 负责 ANSI/VT 控制序列、UTF-8 增量解码和窗口尺寸同步。
- Tmux 创建、重命名、删除和快照均受能力权限控制；终端与删除等危险操作需要再认证。
- 进程表显示 PID、PPID、用户、状态、CPU、内存、启动时间、当前工作目录和命令摘要；工作目录无法读取时显示不可用。
- 工具安装先显示命令并尝试精确 `sudo -n`，确需密码时只经 SSH 标准输入传递已保存 sudo 密码。
- SFTP 支持绝对路径浏览、文件/文件夹上传、文件/目录下载（目录 ZIP）、新建、复制、移动、重命名和递归删除。禁止符号链接下载/复制和目录自复制，删除要求再认证。

## 8. 开发环境与 GPU 软件栈

开发环境服务按需通过 SSH 执行固定盘点命令，不要求被管主机安装 Agent。盘点内容包括发行版、NVIDIA 驱动及 `ubuntu-drivers` 推荐版本、`nvcc`、已安装 cuDNN 包、Python 3、conda、uv 和 APT 包状态；目录工具提供 `du` 容量和受限大文件扫描。工具发现先查 `PATH`，再查用户目录和 `/opt`、`/usr/local` 下的常见绝对路径，避免未激活登录 shell 时误报“未安装”。

所有 GPU 软件栈可选探针必须独立限时并允许降级。驱动推荐、GPU 查询、nvcc、cuDNN、ECC、拓扑或 NVLink 超时时，响应保留已成功字段；ubuntu-drivers 超过 4 秒只返回推荐值不可用说明，其他可选探针才记录 warning，不得把单一可选命令超时升级为整页失败。`nvidia-smi` 非零退出时不得把错误文本当作驱动版本。SSH 连接、认证和指纹错误仍按真实错误处理。

环境后端为 Python `venv`、conda、uv。前端依据盘点结果禁用未安装工具；后端再次校验工具、Python 版本、绝对路径和依赖包名。创建和依赖安装可在复核后 SSH 同步执行，conda YAML 可以导出并上传重建。删除环境只返回脚本，脚本再次检查 `pyvenv.cfg` 或 conda 路径，并拒绝根目录等宽路径。

环境盘点不调用可能长期阻塞的 `conda env list`/`conda list`，而是读取已发现 Conda 根目录、`~/.conda/environments.txt`、`conda-meta` 精确包元数据和 `pyvenv.cfg`。不逐个启动环境 Python；因此环境数量较多时仍受 SSH 总超时约束。前端为每台主机保存扫描根目录，切换目标时同步更新当前目标、环境默认路径和磁盘扫描路径。

驱动、CUDA、cuDNN、uv、Miniconda 和 APT 只生成白名单模板脚本。驱动包必须匹配推荐/受限格式，CUDA/cuDNN 版本来自固定选项，APT 包名经过字符白名单校验。系统级脚本不开放网页执行，因为失败可能使 SSH、内核或软件源不可用；页面明确标注人工审阅边界。

GPU 自检采集 `nvidia-smi` 的枚举、温度、显存、利用率、ECC、拓扑和 NVLink。`nvidia-smi` 无法准确报告 PyTorch allocator 显存碎片，因此接口返回不可用原因而不是伪造百分比；GPU 利用率高而显存低只产生排查提示。

## 9. GPU 调度当前边界

当前调度模型以物理节点 + GPU UUID 为键，支持全局/主机/单卡开关、利用率/显存空闲判定、进程保护、Tmux/直接 Shell、有限重试和冻结状态。修改调度命令会重置运行时状态并写审计。抢占、优先级、多级空闲任务、命令版本快照和泄漏预测留待重构后的版本，不在当前 API 隐式宣称支持。

## 10. 数据、安全和部署

- 数据目录 `0700`，数据库、备份和主密钥 `0600`；主密钥不进入数据库或仓库。
- Session 使用 HttpOnly/SameSite Cookie；写请求要求 CSRF；敏感接口需要重新验证当前平台密码。
- SSH 指纹采用服务端 TOFU，变化时拒绝连接；审计记录用户、来源、操作、对象、结果、request ID 和错误摘要。
- 默认 `127.0.0.1:8000`，生产通过 systemd 和一个 Gunicorn 实例运行。目录迁移必须停止旧服务、重建 `.venv`、测试后再启动。
- SQLite 使用 WAL；同盘备份不等于灾备。压缩前按保留策略清理，禁止手动删除 WAL/SHM。
- 当前数据库 schema 为 `5`，新增告警忽略/软清理字段采用幂等迁移；数据保留策略优先于高频原始日志，系统不会周期落库 `dmesg/journal` 全文。

## 11. 接口验收要点

必须通过以下检查：

1. 未登录、未授权、缺少 CSRF、未再认证的接口分别返回 401/403，不靠前端隐藏代替后端校验。
2. 导入逐条返回结果，导出内容无明文凭据，指纹变化不可批量盲信。
3. iowait/inode/TCP/端口在最新样本、历史点位和主机详情中口径一致；`ss` 缺失不影响核心采集。
4. 全局阈值和挂载点覆盖能触发并恢复真实告警，筛选跨分页生效，CSV 与筛选条件一致。
5. 开发环境工具缺失时选项置灰；三种环境后端、依赖白名单、YAML 大小限制和删除脚本边界均有测试。
6. GPU/系统方案只返回脚本；APT 六种动作、推荐驱动和 CUDA/cuDNN 固定版本均有测试，不能通过接口直接执行系统级方案。
7. 目录迁移后新 `.venv` 可运行，健康检查正常且端口只有一组 Gunicorn。

完整命令：

```bash
.venv/bin/python -m pytest -q
node --check monitor/static/app.js
.venv/bin/python -m compileall -q monitor tests scripts gunicorn.conf.py
.venv/bin/python -m pip check
```

新增需求若涉及任意远程脚本、权限范围隔离、通知网关或调度状态机，必须先更新本规格、测试案例和容量模型，再进入实现。
