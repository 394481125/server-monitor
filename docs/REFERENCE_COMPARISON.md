# 参考项目对比与实施范围

## 结论

`References-for-other-projects/RackTop-main` 是 React + Tauri + Rust 的本地 GPU 工作台；Server Monitor 是 Flask + SQLite 的服务端监控和受控运维平台。两者都关注 GPU 资源，但运行边界不同，因此只迁移能够复用真实服务器缓存、权限和后端 SSH 通道的能力。

| 能力 | RackTop 的优势 | Server Monitor 的现状 | 本项目处理 |
| --- | --- | --- | --- |
| 集群总览 | 浅色统计摘要、服务器/GPU 卡片 | 已有主机卡片和指标条 | 吸收视觉层级，补充 GPU 总数、空闲 GPU、活动告警统计 |
| 空闲算力 | 可按空闲资源发现机器 | 已有 GPU 利用率、显存和进程采样 | 新增 `/api/idle-gpus` 和“空闲算力”一级页面，支持显存/利用率/进程/状态筛选 |
| 历史趋势 | 热力图和资源历史 | 已有分层历史点和 Canvas 曲线 | 保留现有历史 API/曲线，避免引入大型前端依赖 |
| 终端、日志、进程 | 桌面工作区整合 | 后端 WebSocket 终端、进程和审计 | 继续使用服务端会话；空闲 GPU 卡片可直接打开终端 |
| SSH Config / ProxyJump | 本地导入和本地 Agent | 服务端凭证库、跳板机中转、指纹校验 | 不迁移本地凭证体系，保持浏览器不接触跳板机凭证 |
| 项目/数据集/模型 | 本地任务工作流 | 监控、调度和开发环境方案 | 暂不迁移，避免引入另一套文件同步和任务模型 |
| 桌面通知和 Tauri | 原生桌面能力 | 网页告警、Apprise 和审计 | 保留服务端通知策略，按主机和事件分别勾选 |
| X11 图形转发 | 桌面环境可调用本地能力 | 浏览器 xterm 只有字符通道 | 不提供浏览器 X11 按钮；需要 GUI 时使用本地 `ssh -X` |

## 已实现的 RackTop 风格改进

- 总览顶部采用六项统计带，突出主机健康、GPU 容量和待处理告警。
- 主机和空闲 GPU 使用浅色、低对比边框、状态徽标和明确空状态，适合扫描多台服务器。
- 空闲算力页面把“发现资源”变成独立工作流：筛选、查看主机、打开终端都在同一页面完成。
- 移动端收窄统计带和筛选网格，避免按钮、标签和数字重叠或横向溢出。

## 安全边界

空闲算力只读最新可信采样，不触发远端连接和调度。终端、文件、凭证、跳板机和通知继续遵循现有权限、CSRF、elevated、指纹和审计规则。任何“不确定”的 GPU 状态都不会显示为可用，防止陈旧数据诱导任务落到错误设备。

## 验证

`tests/test_idle_gpu_discovery.py` 覆盖空闲判定、阈值筛选、未知/忙碌/有进程排除、API 参数校验和 dashboard 汇总；`tests/acceptance/e2e.py` 使用模拟 GPU 采集完成浏览器流程；`tests/acceptance/browser.js` 额外检查真实页面导航、筛选控件和无横向溢出。
